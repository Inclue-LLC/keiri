# 入金消込（社内用）

INVOY の請求書 CSV と、三井住友銀行・GMOあおぞらネット銀行の入出金明細 CSV を取り込み、
請求書と入金を照合して消込候補を提示する社内向け Web アプリです。**最終確定は必ず人が画面で行います。**

- 構成: Python 3.9+ / FastAPI / SQLite / Jinja2（外部サービス・CDN 不使用）
- データ: `data/keiri.db`（SQLite 1ファイル）

## セットアップ

### かんたん起動（Mac）

```bash
./start.sh
```

初回はライブラリのインストールと最初のユーザー作成を行い、ブラウザが自動で開きます。2回目以降は起動のみです。

### 手動で行う場合

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# 最初のユーザーを作成（2人目以降は画面の「ユーザー」から追加可）
python -m app.cli create-user keiri

# 起動
uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000
```

ブラウザで http://127.0.0.1:8000 を開いてログインします。
`sample_data/` に動作確認用の CSV があります。

### 本番運用の注意

- 社外からアクセスさせる場合は nginx 等のリバースプロキシで HTTPS 化し、`KEIRI_COOKIE_SECURE=1` を設定してください。
- `data/` ディレクトリ（DB とセッション署名鍵）を定期的にバックアップしてください。
- パスワードを忘れた場合: `python -m app.cli reset-password <ユーザー名>`

### 環境変数

| 変数 | 既定値 | 内容 |
|---|---|---|
| `KEIRI_DATA_DIR` | `./data` | DB・署名鍵の保存先 |
| `KEIRI_SECRET_KEY` | 自動生成 | セッション Cookie の署名鍵 |
| `KEIRI_FEE_TOLERANCE` | `880` | 「手数料差引の可能性あり」とみなす差額の上限（円） |
| `KEIRI_DATE_WINDOW_BEFORE_ISSUE` | `7` | 請求日の何日前からの入金を妥当とみなすか |
| `KEIRI_DATE_WINDOW_AFTER_DUE` | `45` | 支払期限の何日後までの入金を妥当とみなすか |
| `KEIRI_COOKIE_SECURE` | `0` | HTTPS 運用時は `1` |
| `KEIRI_SESSION_MAX_AGE` | `28800` | ログインの有効期間（秒） |

## 使い方

1. **CSV取込** で INVOY の請求書 CSV、各銀行の明細 CSV をアップロード（Shift_JIS / UTF-8 どちらでも可）
   - 同じ請求書番号を再取込すると内容を更新（確定済みは更新しない）。INVOY のステータス（下書き/請求済）に関係なく取り込む
   - 銀行明細は入金行のみ取り込み。期間が重なる CSV を取り込んでも重複しない
2. **請求書** 一覧でステータスを確認し、「要確認」の請求書を開いて候補の入金を確認 →「この入金で確定」
   - 名義が一致しない候補は、確定時にその振込名義を取引先の別名として登録できる
   - 候補に出ない入金は「未消込の入金から探す」で名義・金額検索して確定できる
   - 現金・相殺など明細がない場合は「明細なしで入金済にする」（理由必須）
   - 確定は取り消せる
3. **取引先・別名** で振込名義の別名（親会社名義・個人名義など）を登録すると、次回以降の照合に使われる

確定・取消・取込・別名変更などの操作は「ユーザー」画面の操作履歴に記録されます。

## 照合ルール

請求書ごとに、まだ消込されていない入金から次の条件で候補を出します。

| 観点 | 判定 |
|---|---|
| 金額 | 入金額 = 請求額 →「金額一致」／ 請求額 − 入金額 が 1〜880円 →「**手数料差引の可能性あり**」／それ以外は候補外 |
| 振込名義 | 取引先名・カナ名・登録済み別名と比較。半角/全角、法人格（`ｶ)` `(ｶ` `ｶﾌﾞｼｷｶﾞｲｼﾔ` `株式会社` など）、小書き文字（ｬ→ﾔ）、長音、振込依頼人コードの違いは吸収。類似度 85% 以上で「一致」、60% 以上で「類似」 |
| 日付 | 入金日が「請求日 − 7日」〜「支払期限 + 45日」なら「日付妥当」 |

- 金額一致の場合は「名義が類似以上」または「日付妥当」のどちらかを満たせば候補
- 手数料差引の場合はノイズを避けるため「名義が類似以上」が必須

### ステータス

| ステータス | 条件 |
|---|---|
| 入金済 | 人が確定した消込がある |
| 要確認 | 未確定で、入金候補が1件以上ある |
| 期日超過 | 未確定・候補なしで、支払期限を過ぎている |
| 未入金 | 未確定・候補なしで、支払期限前（または期限未設定） |

## CSV の列について

列名は候補リストから自動判定します（ヘッダー前に口座情報などの行があっても可）。
実際の CSV で列が認識されない場合は `app/csv_import.py` の `INVOICE_COLUMNS` / `BANK_COLUMNS` に列名を追加してください。

- **INVOY**（請求書一覧の CSV 出力）: `請求書番号,件名,請求先,請求額,ステータス,お支払い期限,カード請求,決済手数料,備考`
  - 請求日の列がないため、請求書番号の先頭8桁（例: `20260105-1` → 2026-01-05）を請求日として扱う
  - `備考` は請求書詳細に表示（「○○の請求書に合算」などの確認用）
- **三井住友銀行**: 年月日・お引出し・お預入れ・お取り扱い内容・残高（和暦 `R08.04.01` 形式も可）
- **GMOあおぞらネット銀行**: 日付・摘要・入金金額・出金金額・残高

## 現状の制約

- 複数請求書をまとめた1回の入金、1請求書の分割入金は自動候補に出ません（「明細なしで入金済にする」にメモを残して対応。備考で「別請求書に合算」とした請求書も同様）
- INVOY・各銀行の CSV 列名は一般的な形式を想定しています。実データでの初回取込時に結果を確認してください
