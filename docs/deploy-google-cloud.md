# Google Cloud で公開する手順

入金消込アプリを Google Cloud（Firebase と同じ基盤）で公開する手順です。

- **Cloud Run**: アプリを動かす場所（GitHub のこのリポジトリから自動でビルド・公開）
- **Firestore**: データの保存先（東京リージョン）
- **Google アカウントでログイン**: `@inclue-llc.jp` のアカウントだけがログインできる

作業はすべてブラウザの管理画面で行います。**会社の Google アカウント（@inclue-llc.jp）でログインして作業してください。**
（画面の文言は変わることがあります。見当たらない場合は近い名前のメニューを探してください）

---

## 1. プロジェクトを作る

1. https://console.cloud.google.com/ を開く
2. 画面上部のプロジェクト選択 →「新しいプロジェクト」
3. プロジェクト名: `keiri`（任意）、組織: `inclue-llc.jp` →「作成」
4. 作成したプロジェクトが選択されていることを画面上部で確認

## 2. 課金を有効にする

1. 左上メニュー →「お支払い」→ 請求先アカウントをリンク（クレジットカードを登録）
2. 念のため「予算とアラート」で月 1,000 円などの予算アラートを設定しておくと安心です

> 社内数名での利用なら、Cloud Run・Firestore とも無料枠に収まる見込みです。
> 公開のたびに保存されるアプリのイメージ（Artifact Registry）に数十円程度かかることがあります。

## 3. Firestore（データベース）を作る

1. 上部の検索欄で「Firestore」を開く →「データベースを作成」
2. **Native モード**（「Firestore ネイティブ モード」）を選ぶ
3. データベース ID: `(default)` のまま
4. ロケーション: **asia-northeast1（東京）**
5. セキュリティルール: **本番環境モード**（外部から直接は読めない設定。アプリはサーバー側から読み書きします）
6. 「データベースを作成」

## 4. Cloud Run にアプリを公開する

1. 検索欄で「Cloud Run」を開く →「サービスを作成」（「コンテナをデプロイ」→「サービス」）
2. **「リポジトリから継続的にデプロイする（ソースまたは関数）」** を選び、「Cloud Build を設定」
   - API の有効化を求められたら「有効にする」
   - リポジトリ プロバイダ: GitHub →「認証」→ GitHub で Google Cloud Build アプリをインストールし、`inclue-llc/keiri` へのアクセスを許可（組織の管理者の承認が必要な場合があります）
   - リポジトリ: `inclue-llc/keiri`
   - ブランチ: `^claude/wizardly-clarke-xstnyy$`
   - ビルドタイプ: **Dockerfile**（ソースの場所: `/Dockerfile`）→「保存」
3. サービス名: `keiri`、リージョン: **asia-northeast1（東京）**
4. 認証: **「公開アクセスを許可する」（未認証の呼び出しを許可）**
   - アプリ自身が Google ログインで利用者を確認するため、ここは公開にします
5. 「コンテナ、ボリューム、ネットワーキング、セキュリティ」を開く
   - 「変数とシークレット」→ 環境変数を追加: `KEIRI_ALLOWED_DOMAIN` = `inclue-llc.jp`
   - 「設定」の自動スケーリング（またはサービスのスケーリング）: 最小インスタンス数 `0`、**最大インスタンス数 `1`**
6. 「作成」→ 数分待つと、画面上部に `https://keiri-xxxxxxxx.asia-northeast1.run.app` のような URL が表示されます
   - この時点で開くと「Google ログインが未設定です」と表示されます（手順 6・7 で設定します）

## 5. アプリに Firestore を使う権限を付ける

1. Cloud Run のサービス `keiri` →「セキュリティ」タブで **サービス アカウント** を確認（`数字-compute@developer.gserviceaccount.com` など）
2. 検索欄で「IAM」を開く →「アクセスを許可」
   - 新しいプリンシパル: 1 のサービス アカウント
   - ロール: **Cloud Datastore ユーザー**（Cloud Datastore User）→「保存」

> 権限が足りないと、アプリを開いたときにエラー（500）になります。

## 6. Google ログインの設定（OAuth クライアント）

1. 検索欄で「Google Auth Platform」（または「OAuth 同意画面」）を開く →「開始」
   - アプリ名: `入金消込`、ユーザーサポートメール: 自分のアドレス
   - 対象: **内部**（社内のアカウントのみ）
   - 連絡先メール: 自分のアドレス →「作成」
2. 「クライアント」→「クライアントを作成」
   - アプリケーションの種類: **ウェブ アプリケーション**、名前: `keiri`
   - 承認済みのリダイレクト URI: 手順 4 の URL の末尾に `/auth/callback` を付けたもの
     例: `https://keiri-xxxxxxxx.asia-northeast1.run.app/auth/callback`
   - 「作成」→ **クライアント ID** と **クライアント シークレット** が表示されるので控える

## 7. ログイン設定をアプリに入れる

1. Cloud Run のサービス `keiri` →「新しいリビジョンの編集とデプロイ」
2. 「変数とシークレット」に環境変数を追加
   - `GOOGLE_CLIENT_ID` = 手順 6 のクライアント ID
   - `GOOGLE_CLIENT_SECRET` = 手順 6 のクライアント シークレット
3. 「デプロイ」

## 8. 使う

手順 4 の URL を開き、「Google アカウントでログイン」→ 会社のアカウントを選ぶとログインできます。
URL をブックマークしてください。社内の他の人も同じ URL から会社のアカウントでログインできます（初回ログイン時に自動で登録されます）。

---

## その後の運用

- **アプリの更新**: GitHub のブランチ `claude/wizardly-clarke-xstnyy` が更新されると、自動でビルド・公開されます
- **利用者をさらに絞る**: 環境変数 `KEIRI_ALLOWED_EMAILS` にメールアドレスをカンマ区切りで入れると、その人だけがログインできます
- **退職者**: Google Workspace でアカウントを停止すれば、アプリにもログインできなくなります
- **データのバックアップ**: Firestore の「障害復旧」→「バックアップ」で日次バックアップを設定できます（少額の費用がかかります）

## うまくいかないとき

| 症状 | 確認すること |
|---|---|
| 開くとエラー（500） | 手順 5 の権限。Cloud Run の「ログ」タブに `PermissionDenied` が出ていないか |
| 「Google ログインが未設定です」 | 手順 7 の環境変数 2 つ |
| Google の画面で `redirect_uri_mismatch` | 手順 6 のリダイレクト URI が Cloud Run の URL + `/auth/callback` と完全に一致しているか |
| 「inclue-llc.jp のアカウントでログインしてください」 | 個人の Gmail ではなく会社のアカウントを選んでいるか |
| ビルドが失敗する | Cloud Build の「履歴」でエラー内容を確認 |
